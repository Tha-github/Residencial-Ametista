## Alteração desta revisão

O ESLint percorria as saídas voláteis do Playwright e falhava com `ENOENT` se `test-results/` ainda não existisse ou estivesse sendo criada. `eslint.config.js` agora ignora `test-results/` e `playwright-report/`, além das pastas geradas já ignoradas. Isso remove a interferência do relatório de testes no lint do código-fonte.

## Execuções e resultados

- `npm run build` em ambiente local padrão: passou; foram gerados 193 artefatos de imagem incluindo fixtures da rota de demonstração. Um aviso Vite indica que o JSON de conteúdo é importado de forma estática e dinâmica.
- `npm run build` com `PUBLIC_DEPLOY_ENV=production` e `PUBLIC_SITE_URL=https://residencial-ametista.example`: build de produção passou e gerou apenas 20 arquivos em `dist/client`; o placeholder `.example` serve somente para validar compilação e não representa domínio implantado. `dist/client` não contém source maps. O build exclui as rotas de amostra de desenvolvimento.
- `npm run typecheck`: passou, 0 erros/avisos/dicas.
- `npm run lint`: 0 erros; 1 aviso já existente em `scripts/generate-test-images.mjs` por `console`.
- `npm test`: 82 testes em 6 arquivos passaram.
- `npm run test:e2e`: os 80 casos reportaram `ok` (20 em cada viewport: 320, 414, 768 e 1366 px), mas o processo não encerrou depois do último caso; foi interrompido após registrar todos os resultados. Portanto, não houve código final de sucesso do runner.
- `npm audit --omit=dev` e `npm audit`: ambos concluíram com `found 0 vulnerabilities` após liberação de acesso ao registry.

## Pendências para fechamento operacional

1. Repetir auditoria npm em CI antes de releases, pois o resultado muda conforme novos advisories.
2. Trocar o hostname `.example` por `PUBLIC_SITE_URL` definitivo no build/deploy.
3. Em staging, testar rotas, redirects, headers, compressão, cache, imagens, Maps/CTA e realizar Lighthouse mobile e desktop; registrar LCP, INP, CLS e console/network.
4. Com usuário de teste autorizado no Cloudflare Access, validar login/logout, autorização, edição, upload, persistência, erros e expiração de sessão; não habilitar acesso público para viabilizar teste.
5. Fazer revisão manual com teclado e leitor de tela nas rotas finais e revisar textos alternativos com as fotografias definitivas.
